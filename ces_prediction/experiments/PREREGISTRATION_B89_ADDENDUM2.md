# B.89 addendum 2 - cuDNN-compatible deterministic backward mode

2026-11-22, before ANY B.89 CUDA probe. Parent source review identified that cuDNN recurrent backward requires its recurrent module's training flag: an eval-mode cuDNN LSTM forward does not retain the backward reserve. Running every candidate purely in eval mode would reject fused candidates for the probe's own mode choice instead of testing their registered numerical compatibility and interpreter teardown.

Keep dropout disabled and all weights unchanged, but enable training mode on the recurrent module with its dropout probability explicitly zero for BOTH the CPU native reference and every CUDA candidate. The rest of the model remains eval. No optimizer updates, random dropout or parameter fitting are introduced. Record this effective mode in binding/output metadata. The same real prefixes, matched seed weights, masks/loss, gradient tolerances, warmup/timed/repeated counts, timeouts, normal-exit guards and recommendation-only scope apply. CPU preflight is rerun with the new source/input binding before queuing. No scientific score or runtime result was used to make this correction; B.85/B.88/B.90 are untouched.
