# Author-authorized Claude post-evaluation workflow

2026-11-23. The author requests Claude API integration for substantive reasoning tasks and an agentic research follow-up after the current evaluation. This is a review/planning automation, not a new scientific batch or a manuscript acceptance grader.

The one-shot hidden worker polls the original evaluation without changing it. It must observe normal supervisor exit0, queue completion, original post-audit `passed`, the expected confirmation count, matching selection/readout hashes, and equality of copied audited reports before any B.94 performance is sent to Claude. A failed/interrupted evaluation stops the worker without interpreting partial results. A configurable time limit bounds waiting and paid API work separately; the training deadline is never extended.

Only whitelisted anonymized aggregates are exposed: paired points/cluster intervals and counts across all four designs and both evidence scopes, supplementary comparisons with their row-support limits, actual latency, training-budget summaries, and already checked B.98/B.97 summaries. No raw observations, shot IDs, local absolute paths, credentials, checkpoints, complete repository files or private reasoning are sent. TX/TH architecture semantics, one-seed/full scope versus three-seed/subset, internal VAL versus TEST and the reused-campaign limit are explicit.

Four bounded tool-using Claude stages: Fable evidence ledger; Opus adversarial critique; Fable ranked research plan; Opus final revision. Each stage can query only JSON-pointer evidence and submit structured findings/plans into its own local artifact. No arbitrary filesystem access, shell execution, training, commits or external messaging is provided to Claude. Limit each stage to four paid rounds, preserve requests/responses/usage immediately, and stop explicitly on exhausted/failed calls. A previously started call with no response record is uncertain spend and is never automatically repeated.

The result is a deterministic evidence table plus Claude-attributed research proposals, at most three ranked candidates, one immediate next step, overlap with existing experiments, falsifiers, stopped-work rules, both-outcome wording and the needed independent confirmation. JSON pointers are checked by the host; this does not prove the proposals' semantics. TEST-informed ideas are labelled exploratory and require future preregistration. No manuscript number or claim is changed automatically. Outputs are `data/.claude_posteval_20261123/` and `docs/paper/posteval_claude_20261123.{md,json}`; current status is separately reported.
