# TCN MSE 원인: Fable 상세 분석과 Opus 반론

기존 B.105 결과·학습 곡선·소스만 검토했다. 새 학습, 새 잔차 채점, 새 TEST 선택은 없다.
아래 Claude 응답은 원인 가설이며 실험으로 입증된 인과 설명이 아니다.

## 작업자 최종 판정: 원인 가설과 확인된 차이를 분리

**두 Claude 응답의 아래 오류를 먼저 교정해 읽는다. 특히 Opus의 G=GRU 추론은 채택하지 않는다.**

1. 가장 유력한 가설은 GP/hold의 지역 수준을 보존한 잔차 학습과, 절대 온도를 직접 회귀하는 TCN의 귀납편향 차이다. 회귀기는 GP와 이력 통계·fast 변화량을 입력으로 받고 GP 오차만 학습한다. TCN은 held Ti를 입력받지만 출력으로 그대로 더하는 경로가 없고 GP 추정값/동일 통계 요약도 입력받지 않는다. 이는 확인된 구조 차이이며, 어느 요소가 MSE 격차를 만들었는지는 분리 실험 전에는 미확정이다.

2. 같은 내부 TRAIN 파일의 specialized 회귀기와 시나리오 혼합 회귀기에도 D10/F MSE가 낮게 남는다. 따라서 기존 estimator의 추가 적합 파일이나 조건별 재적합만으로 격차를 설명하기 어렵다. 하지만 학습 행 지원과 표현·손실 가중까지 같다는 뜻은 아니다.

3. 확인된 설계상 불일치는 checkpoint 선택과 평가 지원이다. 신경망은 cold-start 등을 포함한 전체 VAL로 checkpoint를 고르고 공통 지원에서 회귀기와 비교한다. V1 F의 선택 VAL은30396행, 공통 VAL은23214행이다. 또한 자원 gate는14셀 평균의 비율이어서 D10 열세가 stale 조건의 VAL 개선으로 상쇄됐다. VAL 통과가 개별 현재값 조건의 우위나 통계적 비열등을 뜻하지 않았다. 이것은 통과 과정을 설명하지만 모델 오차의 단일 원인을 입증하지 않는다.

4. 과제 간섭·일부 큰 잔차·평균 회귀 편향·최적화 부족은 미측정 가설이다. TRAIN objective와 VAL MSE를 직접 빼서 과적합이라 할 수 없다. 네 작업 모두 patience 조건으로 종료했지만 최적화 완료의 증거는 아니다. 입력 추가와 예산 연장이 동시에 달라져 기존 TCN 대비 개선도 원인을 분해할 수 없다.

### Claude 응답의 독립 교정

- **G는 이 결과표에서 인과 GP, H는 hold다.** `b105_merit/readout105.py:specs`는 inputs/{rule}.npz의 문자열 필드 G/H를 비교자로 지정하고, `arrays`가 그 필드 값을 직접 읽는다. `b75_availability/common75.py:file_inputs`는 G를 predict_gp_causal로 만든다. `models90.py`의 방법 코드 G(GRU)는 별도 namespace이며 이번 G 결과와 관계없다. Opus의 GRU 비교 추론은 폐기한다.

- **3600초 adapter는 실제로 확인됐다.** `b105_merit/train105.py:config`가 frozen train92의 config를 덮어쓰고 seconds=3600을 설정한다. 등록·config/checkpoint hash와 별도 audit도 묶여 있다. 검토 요청에 adapter 본문이 빠진 것을 실제 실행 오류나 미해결 예산 불일치로 읽지 않는다.

- **S는 최신 관측 조건이 아니다.** 마지막으로 관측된 결측 이전 CES에서 source가 동결되는 조건이다. D10과 S를 함께 최신 정보 구간으로 묶은 문장은 부정확하다.

- **원본 MSE의 점추정은 행 가중이다.** MSE=평균오차 제곱+오차분산 분해도 동일한 행 가중을 써야 한다. cluster bootstrap으로 구간을 만든다는 이유로 점추정을 같은 비중의 군집 평균으로 바꾸면 다른 estimand가 된다. Opus의 군집 가중 강제 조언은 채택하지 않는다.

- rule_for는 CRC32 기반 modulo7의 결정적 규칙 배정이다. 균형 표집을 의도하지만 매 epoch의 실제 행·파일 노출이 정확히1/7이라는 뜻은 아니다.

- 127행 문맥은 불규칙한 격자에서 정확히1.27초가 아니다. 최신 CES는 매 행 held 입력으로 있으므로 무조건 잃지 않는다. 긴 S 동결/K10의 더 오래된 CES 이력 차이가 실제 오차를 만들었는지는 별도 측정이 필요하다.

- anchor weight norm이나 0 치환 민감도만으로 학습된 원인 기여를 단정하지 않는다. 0 치환은 입력 결합분포를 바꿀 수 있으며 의존도 점검에 한정한다. 동일 업데이트 지점의 개선 비율도 anchor 효과와 학습 예산의 인과 분해가 아니다.

### 다음 진단의 최소 순서 — 아직 실행하지 않음

1. 저장된 VAL 예측의 동일 행에서 signed bias, residual variance, paired 초과 제곱오차와 꼬리 점유율을 분해한다. 꼬리 행 선택은 모델 공통 기준과 각자 기준을 구분한다. 초기 구간/관측 age별 집계를 함께 보되 오차 위치가 특정 기제를 증명한다고 해석하지 않는다.

2. 저장된 VAL 곡선과 예측으로 F/L5·가용 조건·선택 지원을 분리한다. 지금 checkpoint가 현재값 정확도를 희생하는지와, 원래 전체 지원/공통 지원 차이를 확인한다. TEST로 checkpoint나 gate를 다시 선택하지 않는다.

3. CPU 진단이 직접 회귀의 넓은 오차를 지지할 때만, 명시적 hold 또는 GP 잔차 출력 한 변형을 별도 등록해 검증한다. 현 결과만으로 새 GPU 적합을 시작하지 않는다. 이 검토의 권고는 기존 estimator 유지이며, 광범위한 TCN 탐색을 재개할 근거는 없다.

위 진단은 새 과학적 분석이므로 별도 사전등록 후 수행한다. 현재는 원인 가설 검토만 완료했다.

# TCN35가 incumbent보다 MSE가 높은 이유: 원인 진단

**결론:** TCN35의 열세는 최신 보고가 가장 유용한 구간(D10, S)에 집중되어 있고, 이 열세는 VAL에서도 이미 같은 크기로 보였습니다. 게이트는 이를 stale 구간의 VAL 우위로 평균 상쇄해 통과시켰고, 그 우위가 TEST에서 재현되지 않았습니다. 증거와 가장 잘 맞는 설명은 "명시적 hold/GP 기준선 + 잔차" 구조의 부재이지만, 인과적으로 확정된 것은 아닙니다.

표기: **[V]** 검증된 사실, **[H]** 증거가 지지하는 가설, **[U]** 식별 불가능한 추측, **[D]** 실제 코드 결함. 모든 수치는 단위당 1개 유닛, seed 1701, 고정 적합 점추정 범위입니다.

## 3. VAL 게이트 통과와 TEST 실패가 공존한 이유

**비교 대상이 다릅니다 [V].** 게이트(`allocation_gate`, S1)는 VAL에서 fair specialized 대비 평균 정규화 MSE 비율(0.972/1.035/0.988/0.988)을 봅니다. S2와 S3은 TEST에서 incumbent 대비 64개 구간 하한 전부를 요구합니다. 전자는 평균 하나, 후자는 셀별 최악 조건입니다.

**평균의 비율이 열세를 가렸습니다 [V].** 이 부분은 예상되는 산술입니다. VAL에서도 D10/F는 네 유닛 모두 졌습니다.
- `.../val/D10/F/TCN35_over_fair_specialized`: −0.159, −0.159, −0.178, −0.232. 모두 0 배제.
- `.../val/D650/F/...`: +0.128, +0.062, +0.151, +0.094. V1만 0 배제.

Stale 셀은 MSE 절대값이 커서 평균에 더 크게 기여합니다. 예를 들어 V1 규칙별 VAL은 D10 0.155, D1000 0.305입니다.

**TEST에서 바뀐 것은 stale 우위입니다 [V].** D10 열세는 TEST에서도 유지되거나 커졌습니다(specialized 대비 V1 −0.157, V2 −0.167, V3 −0.315, V4a −0.174). 반면 D650/F의 우위는 +0.030, −0.034, −0.037, −0.071로 사라졌습니다.

**원인은 분리되지 않습니다.** 두 설명이 모두 가능합니다.
- 선택 낙관 [H]: TCN 체크포인트는 같은 VAL 집계로 골랐고, 트리는 VAL 선택이 없습니다(`early_stopping=False`). 비대칭이 한 방향입니다.
- 분포 차이 [U]: V3은 모든 방법의 MSE 수준이 VAL에서 TEST로 약 2배 오릅니다(specialized D10/F 31095 → 59908). 수준 차이는 사실이지만, 그것이 TCN에 더 불리하게 작용했는지는 알 수 없습니다.

## 4. TCN35와 TCN22의 비교

**개선은 관측됩니다 [V].** `.../test/D10/F/TCN35_over_TCN22`는 +0.130(V1), +0.160(V2), +0.196(V3), +0.032(V4a)입니다. V4a만 0을 포함합니다.

**귀속은 불가능합니다.** 예산 교란의 방향이 유닛마다 다릅니다.
- V1, V2: TCN22가 `budget_limited`이고 최적이 마지막 epoch입니다. V1에서 동일 업데이트 수(1162)의 VAL은 0.2754 대 0.2888입니다. 총 개선(0.2888 → 0.2307)의 약 1/4만 동일 업데이트 시점에 존재하고, 나머지는 이후의 LR 감쇠 구간에서 나왔습니다.
- V3: TCN22도 855초에 patience로 종료해 예산이 구속 조건이 아니었습니다. 다만 VAL 곡선이 0.395~0.743으로 요동합니다.
- V4a: TCN35가 오히려 더 적게 학습했습니다(12 epoch, 905초 대 17 epoch, 1200초).

따라서 "앵커 채널이 학습 후 실제로 쓰인다"는 것은 [H]입니다. zero-init 덕에 초기 함수는 같지만, 단일 시드에서 궤적이 달라진 효과와 구분되지 않습니다. 35채널 history-only 쌍둥이 모델도 없어, fast 진단 자체의 유용성도 판단할 수 없습니다. 규칙별로 보면 V3 VAL의 S(0.539 대 0.488)와 D1000(0.485 대 0.479)에서는 TCN35가 TCN22보다 나쁩니다.

## 5. 코드 점검

**실행 경로에서 확정된 결함 [D]: 발견하지 못했습니다.** 제공된 발췌 범위에 한정된 판단이며, 결함이 없다는 증명은 아닙니다. 확인한 항목은 다음과 같습니다.
- `build_segments`의 dt_prev, 앵커의 strictly-earlier 조건, 두 헤드의 동일 정규화.
- `anchor13_adapter`의 동일 seg/file 및 정규화 일치 assert.
- 패딩 행은 mask로 손실에서 제외.
- `AnchorTCN`의 RNG 복원과 stem 복사.
- `_build_x_row`는 dt 계산이 틀렸지만 호출되지 않는 사문 코드입니다.

**출처 불일치 1건 [V].** 제공된 `numerical_train_loop`는 `common92`/`model92`를 import하고 confirm 단계를 `(40,1200)`으로 고정합니다. 그런데 TCN35의 wall_seconds는 2434초와 2142초입니다. 3600초로 실제 실행된 B105 루프 본문은 이 발췌로 줄 단위 확인을 할 수 없습니다. 결함이 아니라 감사 공백입니다.

**결함이 아닌 설계상 약점 후보 [H]:**
- 출력이 절대 수준 직접 회귀라서, hold 값의 항등 전달을 stem, GELU, 6개 블록, LayerNorm, 헤드를 거쳐 학습해야 합니다.
- 세그먼트당 epoch마다 규칙 하나만 표집합니다(`epoch_segments`). 규칙별 유효 노출은 약 1/7이고, VAL은 7개 규칙 전부를 균형 평가합니다.
- 학습 손실은 배치 내 행 풀링에 음수 Ti 페널티와 dropout이 더해지고, 선택 지표는 규칙 균형 순수 MSE입니다.
- ReduceLROnPlateau(patience 2)와 early stop(6)이 잡음 큰 VAL에 반응합니다(V3, V4a).

## 6. 현재 집계로 식별할 수 없는 것

- 초과 MSE가 체계적 편향인지, 소수의 큰 잔차인지, 넓게 퍼진 분산인지. 행 단위 잔차 분석이 없습니다.
- 타깃 보고 잡음이 기여하는 몫. F와 L5는 독립적인 참값이 아닙니다.
- 세그먼트 초반(수용장 127행 미충족, cold-start)에 오차가 집중되는지.
- Ti 범위 외삽이나 보정 문제.
- F/L5 및 규칙 간 과제 간섭. 단일 헤드나 단일 규칙 TCN이 없습니다.
- 최적화 부족과 표현 한계의 구분. 학습 목적함수와 VAL의 차이(V3: 0.238 대 0.369)는 깨끗한 일반화 격차가 아닙니다.
- 설계 전체나 초기화에 대한 강건성.

## 7. 최소 진단 (우선순위 순, 각각 별도 사전등록 필요, 실행 약속 아님)

**1. CPU, 저장된 VAL 예측의 잔차 분해.** TEST는 쓰지 않습니다. D10/F와 D10/L5에서 TCN35와 fair specialized에 대해 클러스터 단위로 네 가지를 측정합니다.
- (a) 평균 부호 오차.
- (b) 상위 1% 행의 제곱오차 점유율.
- (c) 세그먼트 내 위치별 MSE(127행 이내와 이후).
- (d) |target − hold| 분위별 MSE.

가설별 예상 결과:
- 원인 1이 맞으면, 초과 오차가 넓게 퍼지고 target ≈ hold인 행에서도 남습니다.
- 꼬리나 cold-start가 원인이면, (b)나 (c)에 집중됩니다.
- 편향이 원인이면, (a)가 0이 아닙니다.

**2. CPU, 저장된 체크포인트의 앵커 사용 감사.** stem 가중치의 열 그룹별 노름(0:13, 16:19, 22:35)을 봅니다. 이어서 VAL에서 앵커 13열을 0으로 둔 순전파로 규칙별 MSE 변화를 측정합니다.
- 변화가 거의 없으면, TCN35와 TCN22의 차이는 예산이나 궤적 쪽으로 기웁니다.
- Stale 규칙에서 MSE가 오르면, 앵커가 실제로 쓰인다는 뜻입니다.

**3. GPU, 진단 1이 "넓게 퍼진 오차"로 나올 때만.** 변형은 단 하나입니다. 출력 = x[16](held Ti) + 헤드로 하고, has_visible=0인 행은 헤드만 씁니다. 그 외 구성, 시드, 예산은 동일하게 둡니다. 판정은 VAL의 D10 셀별 specialized 대비 비율로 사전 지정하고, TEST는 쓰지 않습니다.
- 원인 1이 맞으면, D10 VAL 열세(−16~−23%)가 뚜렷이 줄고 stale 셀은 유지됩니다.
- 변화가 없으면, GP와 요약 특징 또는 최적화 쪽이 남습니다.

어느 결과도 사후 TEST 확인으로 주장할 수 없습니다.

## 8. 연구 결정

- **정확도 목적: incumbent를 유지합니다.** S2와 S3이 모두 실패했고, D10/F는 네 유닛 모두 0을 배제하는 열세입니다. 운영상 이득은 측정되지 않았습니다.
- **TCN: 좁고 식별 가능한 결함 하나만 추적합니다.** 대상은 최신 앵커 구간의 기준선-잔차 구조이고, 진단 1과 2(CPU)까지만 진행합니다. 진단 1에서 식별 가능한 패턴이 나오지 않으면 TCN은 당분간 중단합니다. 폭넓은 아키텍처 탐색은 근거가 없습니다.
- **구조적 새로움은 별개 문제입니다.** 이번 결과는 아키텍처가 본질적으로 열등하다는 증거도, fast 채널이 무용하다는 증거도 아닙니다. 고정 유닛 4개와 단일 시드에서 이 구성이 incumbent에 미달했다는 사실까지만 지지합니다.

## 독립 Opus 반론·수정

# 1차 분석 재검토: TCN35가 incumbent보다 MSE가 높은 이유

**요지:** 1차 분석의 수치는 대부분 정확하지만, 인과 귀속 두 곳이 과합니다. 미정의 키 "G"를 GP로 추정한 부분은 실제 코드와 충돌합니다. VAL 지지(support) 불일치는 누락되었습니다.

## 1. 수치 재확인 (유지)

- **D10/F TCN35/incumbent 비율:** 1.169, 1.159, 1.316, 1.184로 맞습니다.
- **fair specialized/incumbent:** 1.011, 0.994, 1.001, 1.009입니다.
- **fair mixture/incumbent:** 1.050, 1.036, 1.055, 1.022입니다.
- **V3 F의 staleness별 초과율:** D50부터 D1000까지 1.204, 1.151, 1.088, 1.086, 1.004로 맞습니다.
- **V1 동일 업데이트(1162) 비교:** VAL 0.2754 대 0.2888로, 총 개선 중 약 23%만 같은 시점에 존재합니다. 맞습니다.
- **V4a:** 최종 VAL 0.44927, 최적 0.44887로 맞습니다.
- **게이트:** `candidate_to_specialized_ratio`는 평균의 비율입니다(V1: 0.2054/0.2114 = 0.972). 따라서 MSE가 큰 stale 규칙이 더 큰 가중을 받는다는 서술은 산술적으로 옳습니다.

수치 증거는 120셀(VAL 56, TEST 64)입니다. 같은 적합 모델과 겹치는 행을 공유하므로 120개의 독립 반복이 아닙니다. "64개 중 몇 개"식 집계는 증거를 중복 계산합니다.

## 2. 수정이 필요한 주장

**(a) "G = GP 단독일 수 있다"는 철회해야 합니다.**
`TCN_and_blocks`의 `METHODS`/`ARCHITECTURES`에서 'G'는 *lag-conditioned decay GRU*입니다. 셀 키 G가 이 모델이라는 것은 코드가 시사하는 바이지 검증된 사실은 아닙니다. 다만 GP를 가정할 근거는 없습니다. 오히려 G가 맞다면 반대 방향의 신호가 됩니다.
- 명시적 GP가 없는 신경망 G가 `V3_q3/test/D10/F`에서 70679로 TCN35(78786)보다 낮습니다.
- `V4a/test/D10/F`에서도 67250 대 71020으로 낮습니다.
- 다만 V1과 V2에서는 G가 더 나쁩니다.

따라서 "GP 부재"만으로 D10 열세를 설명하기 어렵습니다. 같은 입력에서 TCN 고유의 표현이나 최적화 요인이 있을 수 있습니다. 단, G의 예산, 입력, 선택 조건이 제공되지 않았으므로 이는 약한 신호입니다.

**(b) 원인 1의 근거가 비판별적입니다.**
"D10에서 열세가 최대이고 staleness가 커질수록 감소"하는 패턴은 기준선+잔차 부재와 들어맞습니다. 그러나 최신 정보가 많을수록 incumbent의 개선 여지가 크다는 일반적 설명과도 똑같이 들어맞습니다.
- 최신 held CES, age, flag는 매 행 x[16:19]로 직접 들어갑니다. 따라서 127행 수용장이 "최신 값"을 잃지는 않습니다.
- 손실 가능성은 긴 S 동결 구간이나 K10에서 16개 과거 관측을 질의하는 GP와의 차이뿐이며, 그 빈도나 오차 기여는 측정되지 않았습니다.
- 진단 (c)는 "수용장 손실" 검정이 아니라 cold-start 집중도 측정으로만 해석해야 합니다.

**(c) 누락된 학습/선택 분포 불일치 [V].**
- TCN의 체크포인트 선택 VAL은 규칙별 F 30396행(V1)을 씁니다(`best_rule_aggregate_validation.counts`).
- matching-support VAL 셀과 트리 VAL은 23214행입니다.

즉 TCN은 cold-start와 마스크 타깃을 포함한 넓은 지지에서 선택되었고, 평가는 공통 지지에서 이루어졌습니다. 이것은 "선택 낙관"과 별개의 메커니즘입니다. 다만 방향은 [U]입니다.

**(d) "규칙 노출 약 1/7"은 [U]입니다.**
`epoch_segments`가 세그먼트당 규칙 하나를 고른다는 것은 [V]입니다. 그러나 `B85.rule_for`의 분포는 제공되지 않아 균등하다고 단정할 수 없습니다.

**(e) 최적화 관련 표현.**
'converged'는 patience 6 충족일 뿐입니다. 전역 최적이나 수렴의 증거가 아니며, 1차 분석도 대체로 이 점을 지켰습니다. 과적합 근거로 학습 목적함수와 VAL의 차이를 쓰지 않은 점은 유지합니다. "잡음 큰 VAL"은 V3, V4a의 곡선 요동이라는 관측까지만 사실입니다. 그것이 TEST 열세를 일으켰다는 근거는 없습니다.

**(f) L5와 F.**
두 헤드는 행 지지와 개수가 다릅니다. L5의 MSE가 낮은 것을 잡음 분산의 통제 비교로 읽으면 안 됩니다. 1차 분석이 이 해석을 명시하지는 않았지만, (d) 분위 진단에서도 헤드 간 비교는 금지해야 합니다.

**(g) 잔차 분해의 산술.**
- MSE = 평균오차² + 분산이므로, (a) 평균 부호 오차는 클러스터 가중으로 계산해야 분해 항과 일치합니다.
- (b) 상위 1% 점유율은 두 모델에서 같은 행 집합 기준과 각자 기준을 모두 보고해야 합니다. 그렇지 않으면 "소수 큰 잔차"를 판별할 수 없습니다.

**(h) 코드 감사.**
- 확정 결함 없음, `_build_x_row`는 사문 코드라는 판단은 유지합니다.
- 루프 발췌가 `(40,1200)`인데 TCN35는 3600초로 실행된 점은 감사 공백으로 유지합니다.

## 4. 진단 우선순위 (사전등록, TEST 미사용)

1. **CPU, 저장된 VAL 예측을 matching support와 TCN 전체 지지로 각각 분해.**
   - 측정: D10/F와 S/F에서 클러스터 가중 평균오차, 동일 행 기준 상위 1% 점유율, 세그먼트 초반 대비 이후의 MSE.

   - 초반이나 꼬리에 집중되면 cold-start나 선택 지지 문제를 지지합니다.
   - 두 지지 사이의 격차가 크면 (c)를 지지합니다.
2. **CPU, 셀 키 G/H의 정의와 실행 조건 확인 및 TCN35 체크포인트 앵커 감사.**

   - 감사: stem 열 노름과, 앵커 13열을 0으로 둔 순전파의 규칙별 VAL MSE.
   - 변화가 없으면 TCN35 대 TCN22의 차이는 예산이나 궤적 쪽으로 기웁니다.
3. **GPU (1에서 넓게 퍼진 오차가 나올 때만):** 출력 = x[16] + 헤드, 단일 변형. 사전 지정된 VAL D10 기준으로만 판정합니다.

**결정:** 정확도 목적에서는 incumbent를 유지합니다. TCN은 위 CPU 진단까지만 진행합니다.
