# 기존 그림의 로컬 일치·독해·외부 제공 범위 점검

> **정정 — 그림 6의 가로 막대:** 초기 점검에서 “bootstrap 신뢰구간이 아니다”라고 쓴 판단은 잘못되었다. 기존 산출 코드를 다시 읽어 확인한 결과, 가로 막대는 **등가 보고 간격 k′의 95% shot-cluster bootstrap 구간**이다. RMSE의 세로 구간이 아니라, 각 재표집에서 T0 곡선과 TX 오차를 함께 이용해 계산한 등가 간격의 가로 구간이다. 아래 관련 설명을 정정했다. 그림이나 통계를 새로 계산하지 않았다.

검토 범위는 기존 일곱 standalone plot PDF, 이를 포함한 `ppcf_revision/main_ppcf.pdf`, 현재 HTML의 개별 그림 PNG다. 기존 파일을 읽고 로컬에서 렌더했으며 그림 생성기 실행, 모델 적합, 통계 재계산, 외부 API 호출은 하지 않았다. 로컬 렌더와 비교 보조 파일은 ignored `data/.thesis_longform/figure_verification/`에 있다. 이 문서 외의 공개 파일은 수정하지 않았다.

## 1. 실제 확인 결과

비교는 standalone PDF 첫 페이지의 decoded content stream을 읽고, compiled PDF에서 해당 plot을 포함한 최상위 Form XObject의 decoded stream과 직접 대조했다. 일곱 그림 모두 정확히 같았다. 이는 그림의 drawing stream을 동일하게 가져왔다는 확인이며, 원자료나 통계 결과를 다시 계산한 검증은 아니다. 글꼴과 배치의 보이는 결과는 별도로 렌더를 직접 보았다. HTML은 `source-exhibit`의 해당 그림에서 base64 PNG를 추출한 뒤, manifest의 페이지·clip에서 PyMuPDF가 생성한 160 dpi PNG와 비교했으며 일곱 개 모두 정확히 같았다. manifest의 PDF 해시도 현재 PDF와 일치한다.

따라서 현재 문제는 잘못된 plot이 섞인 것이 아니라 설명과 시각적 읽기 방식에 있다. 원본 plot을 SVG로 넣으면 긴 영문 캡션까지 이미지 안에 포함한 현재 crop보다 글자 확대가 유리하다. 다만 새로운 한국어 설명을 짧은 제목으로만 대체하면 기존 영문 캡션의 평가 조건이 사라지므로 아래 항목을 복구해야 한다.

## 2. 각 그림의 설명과 배치 점검

### 그림 1 — 자료의 예시와 이력 가용성

- **실제 보이는 내용:** 왼쪽은 선택된 한 방전의 CES 보고온도, 빔 출력, BES·ECEI 상대 수준이다. 세로선은 absent frame에 대응하는 빔 notch를 나타낸다. 회색 구간은 ECEI가 일정하게 유지된 구간이며 이 행들이 분석에서 제거되지 않았음을 뜻한다. 오른쪽은 규칙 S에서 가장 최신으로 허용되는 CES 값의 나이 분포다.
- **한국어 캡션에 필요한 내용:** 예시 방전은 사전에 정한 규칙으로 선택되었으며 전체 캠페인의 평균 궤적이 아니다. 상대 수준은 각 배열 신호의 중앙값에 대한 비이며 온도·밀도 단위가 아니다. 오른쪽은 분석 시간을 영으로 둔 평가 규칙에서 계산한 분포로 실제 보고 도착 시각의 측정이 아니다. 생성기의 histogram은 범위를 넘는 나이를 마지막 bin에 포함하므로, 완전한 오른쪽 꼬리를 모두 표시한 그림으로 읽히지 않게 설명한다.
- **배치:** Dataset의 자료 구성·결측·빔 변조 일정 설명 근처가 적절하다. 실제 시간 예시를 서론의 일반적 개념 그림처럼 쓰지 않는다.
- **독해 불편:** 왼쪽 세 축과 오른쪽 분포는 의미가 크게 다르고 모바일에서 한 번에 축소된다. 패널을 확대할 수 있게 하고, (a)/(b)를 나누어 설명하는 편이 낫다. 회색 음영의 의미를 상태 불량의 확정 원인으로 바꾸지 않는다.

### 그림 2 — 가용 정보의 도식

- **실제 보이는 내용:** 현재 행의 위치, 현재까지의 빠른 표본, 이전 CES 프레임·고정 지연·마지막 notch 이전·성긴 보고의 가용 규칙을 표시한다. 이는 실제 한 방전의 관측점 배열이 아니라 생성기에서 명시한 도식이다.
- **한국어 캡션에 필요한 내용:** 파란 사각형은 사용할 수 있는 CES, 빈 사각형은 가려진 값, 주황색 표시는 absent frame이다. 현재 CES 프레임은 입력이 아니다. 지연은 이력의 나이이며 예측 시계가 아니다. 도식의 지연과 성김 값은 표시를 위한 예시이지 모든 실험 조건의 목록이 아니다.
- **배치:** 방법의 가용성 규칙 문단 바로 뒤가 가장 자연스럽다.
- **독해 불편:** 도식의 각 행을 CES 신호 값의 크기로 오해하지 않도록 세로축이 규칙의 목록임을 설명한다. 모바일에서는 행 이름과 범례가 작아지므로 벡터 확대 또는 가로 스크롤이 도움이 된다.

### 그림 3 — 선택된 시험 방전의 추정 궤적

- **실제 보이는 내용:** 같은 방전의 서로 떨어진 세 시간창에서 보고값과 hold·인과 GP·PCHIP·본선 추정을 겹쳐 그린다. 세 패널은 연속된 한 축이 아니며 세로선은 absent frame이다. TCN 궤적이 아니다.
- **한국어 캡션에 필요한 내용:** 직전 CES 프레임이 보이는 조건이고 표적은 F다. 보고값은 점, PCHIP는 다음 값을 기다리는 오프라인 기준선이다. 해당 방전은 시험 fold에 있을 때 추정되었다. 예시 곡선의 일치만으로 네 검증 설계 전체의 오차를 대신하지 않는다.
- **배치:** 결과의 기준선 비교 표·오차 분포 설명과 가깝게 둔다.
- **독해 불편:** 검은 점이 조밀한 구간에서 hold와 인과 GP 선이 겹치고, 진한 파랑과 연한 파랑을 축소하면 구분하기 어렵다. 원본 확대를 제공하고 선의 의미를 캡션에서 명확히 쓴다. 세 패널의 시간 범위가 다름을 짧게 설명하면 임의의 연속 trace로 읽는 것을 막을 수 있다.

### 그림 4 — 이력의 나이와 오차

- **실제 보이는 내용:** random 설계에서 L5의 RMSE를 이력 지연에 따라 나타낸다. 왼쪽은 KSTAR, 오른쪽은 MAST다. 점선 O는 현재 프레임 판독값을 L5에 대해 채점한 기준이다. KSTAR의 다이아몬드는 규칙 S를 그 조건의 중앙 이력 나이에 표시한 것이다.
- **한국어 캡션에 필요한 내용:** 각 가용 조건에 맞추어 모델을 적합했다. 일정 S의 점은 고정 지연의 공통 행과 다른 S 자체의 행에서 평가된다. 지연축은 로그 축이며 미래 표적을 더 멀리 옮기는 축이 아니다. MAST 현재 입력은 Thomson 산란이고 CES보다 빠른 진단이라는 전제는 없다.
- **배치:** 결과의 오래되거나 성긴 이력 설명 바로 옆이 적절하다. MAST 절에서는 패널 (b)에 연결하되 같은 그림을 중복 삽입할 필요는 없다.
- **독해 불편:** 큰 범례가 왼쪽 plot 안에 있고 여러 곡선이 가까워진다. 원본 SVG에서 확대하면 해결되지만 캡션만 길게 쓰는 것으로 곡선 구분이 해결되지는 않는다. 두 패널의 세로축 범위와 가로축 범위가 서로 다르므로 장치 간 효과 크기를 눈금 높이만으로 비교하지 않게 설명한다.

### 그림 5 — 증가분의 구간

- **실제 보이는 내용:** 조건·검증 설계별 MSE 감소율과 구간을 보여 준다. 왼쪽 KSTAR는 가용성 조건에 따라 색이 나뉘고, 오른쪽 MAST는 다른 지연 조건을 사용한다. 채운 점은 구간이 영을 제외하는 경우다.
- **한국어 캡션에 필요한 내용:** L5의 fast-input 대 history-only 짝비교이며 구간은 각각 KSTAR shot cluster, MAST session을 재표집한 것이다. KSTAR에 chronological 행이 둘 있다고 검증 설계가 다섯 개인 것은 아니다. 둘은 학습 끝점을 달리한 같은 설계의 적합이다. 빈 점은 차이가 확인되지 않았다는 뜻으로 동등성의 표시가 아니다.
- **배치:** 그림 4와 같은 가용성 결과 중 네 설계의 차이를 설명한 문단 근처에 둔다. 그림 4가 오차 크기를, 그림 5가 짝비교 증가분과 구간을 보여 준다는 역할을 구분한다.
- **독해 불편:** 행 이름이 작고 검증 설계 표지가 반복된다. 모바일에서는 이미지 확대가 필요하다. 표시 순서가 성능 순위가 아니며, 왼쪽과 오른쪽 축 범위도 다르다.

### 그림 6 — 보고 간격이 성긴 조건

- **실제 보이는 내용:** random 설계, L5 표적에서 보고 간격을 바꾸었을 때 T0와 TX의 RMSE를 나타낸다. 보조선은 TX의 특정 성긴 조건 오차와 같은 오차를 갖는 T0의 등가 간격 위치를 나타내고, 가로 막대는 그 등가 간격의 shot-cluster bootstrap 구간을 표시한다.
- **한국어 캡션에 필요한 내용:** 가로 막대는 **등가 간격 k′의 95% cluster-bootstrap 구간**이며, RMSE의 세로 구간이 아니다. `readout78.py::eqrate()`는 재표집마다 T0 곡선과 해당 TX 오차로 `eq_ln()`을 계산하고 양쪽 분위수에서 구간을 구한다. `fig_v2.py::fig_sparse()`는 산출물의 `equivalent rate.cluster.k_prime`을 읽어 프레임 간격 단위로 환산한 양 끝을 `xerr`로 그린다. 실제 CES 하드웨어의 시간해상도가 그만큼 개선되었다는 결과가 아니라 동일 표적·오차 척도에서의 비교다. 이 등가 관계를 다른 설계에 그대로 일반화하지 않는다.
- **배치:** 성긴 보고 간격에 관한 결과 문단 바로 뒤가 적절하다.
- **독해 불편:** 가로 막대가 RMSE 불확실성으로 읽히지 않도록 등가 간격의 구간임을 설명해야 한다. 축은 로그 간격이며 O는 현재 프레임 판독의 기준선이다. 원래 이 plot은 다른 그림보다 종이 폭이 좁으므로 HTML에서 전폭 확대할 때 글자가 과대해질 수 있다. 최대 표시 폭을 별도로 주면 좋다.

### 그림 7 — 마지막 블록의 적용 범위

- **실제 보이는 내용:** 왼쪽은 random 설계·규칙 S·L5에서 shot 블록별 증가분의 점과 구간이다. 빔 특징을 양쪽 모델에 제공한 대조도 함께 있다. 오른쪽은 notch 전후의 관측 신호 응답을 블록별로 요약한 점이며, 신뢰구간이 없는 사후 관찰이다.
- **한국어 캡션에 필요한 내용:** 왼쪽의 빈 점은 마지막 블록의 증가분이 확인되지 않음을 표시한다. 오른쪽에는 구간이 없고 원인 규명 결과도 아니다. 가로축은 시간 파형이 아니라 shot 블록의 범주다. 블록을 H-mode·RMP 등 검증되지 않은 물리적 운전 상태로 바꾸어 부르지 않는다.
- **배치:** 마지막 방전 블록의 한계 설명 바로 옆이 적절하다. 통합된 결과 소절에 MAST와 한계가 함께 있더라도 이 그림의 대상은 KSTAR임을 제목에 드러내면 좋다.
- **독해 불편:** 두 패널의 기준선이 다르다. 왼쪽은 감소율의 영, 오른쪽은 notch 전후 비의 일이다. 같은 방향의 높고 낮음을 같은 의미로 읽지 않게 설명한다. 회귀의 통계적 성립 범위와 신호의 사후 양상을 나란히 제시했을 뿐 진단 상태 변화의 인과를 증명하는 그림은 아니다.

## 3. 외부 API 제공 범위에 관한 패널별 판정

이 판정은 공개 여부가 아니라 **개별 관측 trace를 보내지 않고 비식별 집계 결과만 제공한다**는 현재 작업의 전송 규칙을 적용한 것이다. 파일이 저장소에 있거나 그림으로 표현되어 있다는 이유만으로 전체 이미지를 전송 가능하다고 판단하지 않았다.

| 그림·패널 | 로컬에서 확인한 데이터 성격 | 이번 API 제공 권고 |
|---|---|---|
| 그림 1(a) 전체 | 하나의 선택 방전에서 읽은 CES·NBI·BES·ECEI 시계열. 채널 평균·정규화를 해도 단일 방전의 시간별 관측이다. | **제외.** 관측 trace와 shot 식별자가 포함된다. |
| 그림 1(b)만 | 규칙 S의 채점 행 전체에서 계산한 이력 나이 histogram과 집계 위치. | **이 패널만 분리하면 제공 가능 범위.** 실제 보고 지연 측정으로 설명하지 않는다. |
| 그림 2 전체 | 생성기에 `schematic=True`로 기록된 규칙 도식. 실제 방전의 관측값이 아니다. | **제공 가능 범위.** 규칙 이해를 검토할 자료다. |
| 그림 3 전체 | 하나의 시험 방전에서 관측값·저장 추정값을 시간별로 그린 세 trace. | **제외.** 추정선만 남겨도 개별 방전의 상세 추정 trace가 남으므로 이번 aggregate 검토에는 불필요하다. |
| 그림 4 전체 | 조건별 오차 집계 곡선. 단일 프레임 관측이 아니다. | **제공 가능 범위.** 조건별 적합·평가 집합 차이를 설명한다. |
| 그림 5 전체 | 조건별 짝비교 skill과 재표집 구간. | **제공 가능 범위.** 개별 관측·예측 배열을 붙이지 않는다. |
| 그림 6 전체 | 성긴 보고 조건별 RMSE와 등가 간격 집계. | **제공 가능 범위.** 막대의 의미를 함께 제공한다. |
| 그림 7(a)만 | 블록별 평가 증가분과 구간. | **제공 가능 범위.** 필요하면 블록을 앞·중간·뒤와 같이 비식별 범주로 설명할 수 있으나 새로운 값은 만들지 않는다. |
| 그림 7(b) | `fig_v2.py::fig_limits()`가 `make_tables_v2.parse_last_block()`을 통해 `b75_last_block.md`의 (7) 블록별 notch 응답 요약을 읽는다. 단일 notch의 시간 trace가 아니라 여러 notch의 블록별 요약 점이다. | **원자료 trace 자체는 아니다.** 다만 이번 검증의 안전한 최소 집합에서는 제외해도 충분하다. 제공하려면 사후 블록 집계·구간 없음·기전 미확정임을 명시하고, event별 값이나 source cache를 동봉하지 않는다. |

그림 7(b)를 단순히 “notch 직후 첫 행”이라는 세로축 제목만 보고 개별 관측이라고 판정하는 것은 정확하지 않다. 생성기는 블록별 요약표에서 값을 읽으며, 원본 시간열을 그 패널에 직접 그리지 않는다. 반대로 그림 1(a)의 배열 평균은 단일 방전의 시간별 관측이므로 “평균”이라는 이름만으로 허용된 집계 자료가 되지 않는다.

안전한 최소 이미지 묶음은 **그림 1(b), 그림 2, 그림 4, 그림 5, 그림 6, 그림 7(a)**다. 이 집합으로 축·범례·기준선·가용성·구간 해석의 주요 사항을 외부에서 검토할 수 있다. 나머지는 이 문서의 로컬 직접 확인으로 다룬다.

패널을 외부에 제공할 때에는 원본 PDF/SVG의 `viewBox`나 클리핑만 바꾸어 보내지 않는다. 화면에서는 가려졌더라도 파일 내부에 금지된 왼쪽 trace가 남을 수 있다. 허용 패널만 로컬에서 PNG로 렌더하여 실제 픽셀을 확인한 뒤 그 PNG만 전송하는 방법이 명확하다. 참고 가능한 source-PDF 좌표 범위는 problem의 오른쪽 패널 약 `[303, 0, 453.54, 297.64]`, limits의 왼쪽 패널 약 `[0, 0, 225, 192.76]`이다. 이는 제공용 패널을 만드는 출발 범위이며, 최종 PNG의 축·라벨 포함과 금지 패널 미포함을 다시 직접 확인해야 한다.

`figv2_problem.json`에는 단일 방전의 시간·온도·빔·빠른 신호 배열도 함께 들어가므로 오른쪽 패널의 집계만 검토하더라도 JSON 전체를 보내면 안 된다. `figv2_nowcast` 또는 trace 계열 JSON도 동일하다. plot 생성기를 외부 검토 자료로 붙이는 경우에는 원자료 경로나 주석보다 실제 데이터 payload가 함께 포함되는지를 별도로 확인해야 한다. 이번 로컬 점검에서는 외부로 어떤 파일도 전송하지 않았다.

## 4. 원본 plot으로 교체한 뒤 권장되는 마지막 확인

1. 원본 standalone PDF와 compiled PDF의 drawing stream 일치를 현재와 같이 확인하고, 원본 SVG/PNG의 provenance를 해당 standalone 파일에 연결한다. PDF가 재빌드되면 xref 번호를 고정값으로 재사용하지 말고 그림 크기·페이지와 Form을 다시 찾는다.
2. HTML의 각 그림을 실제 확대·축소해 보고 축·범례·캡션이 해당 본문 주장과 함께 읽히는지 확인한다. 일곱 그림 모두 한 번씩만 배치하고, 다른 절은 링크로 참조한다.
3. 원본 plot에는 없는 기존 영문 캡션의 평가 표적, 정보 시점, 검증 설계, 구간 단위와 사후 관찰 여부를 한국어 캡션에 보존한다.
4. 그림 4와 5의 MAST 패널을 KSTAR 조건으로 설명하지 않고, 그림 7(b)의 무구간 사후 관찰을 유의성·기전 증거로 바꾸지 않는다. 그림 6의 가로 막대는 등가 간격의 95% shot-cluster bootstrap 구간이며 RMSE의 세로 구간과 구분한다.
5. 표 11은 TCN 시간표이며 GP·boosting 시간표가 아니다. runtime 설명 근처에 있더라도 본선 추정기의 계산 비용을 입증하는 표로 인용하지 않는다. 현재 일곱 plot 자체에도 GP 추론시간 분포 그림은 없다.

일치 검증과 시각 QA는 수치 재계산을 대신하지 않는다. 이번 확인에서 얻은 결론은 현재 HTML의 그림들이 기존 원고에 포함된 원본 plot과 같은 내용이며 잘못된 대체 그림이 없다는 점, 그리고 캡션과 패널별 외부 제공 범위를 위와 같이 구분해야 한다는 점이다.
