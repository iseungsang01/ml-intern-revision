# 다음 GPU 세션의 방향: 현행 estimator 대비 merit부터 판정

상태: **Fable 검토를 반영한 최종 방향 문서. 실행 사전등록/학습 코드는 아직 아님. 오늘 새 학습·새 TEST 채점 없음.** 저자의 “내일 GPU” 지시에 따른 준비이며 예약 작업을 설치한 것은 아니다.

## 결론과 앞선 보고의 정정

기존 22채널 TCN의 단순 재학습·예산 연장·폭넓은 구조 탐색은 종료한다. 먼저 현행 estimator와의 정확도 및 시나리오 운용 가치를 판단한다. P1 물리 추정기와 불확실도 연구는 이 판정 뒤의 별도 과제로 둔다. GPU가 있다는 이유만으로 새 적합을 배정하지 않는다.

“직접 비교가 없다”는 작업자의 앞선 설명은 잘못이었다. B.94 JSON의 `supplementary_tree_pairs`에 TCN과 GP+부스팅 간 paired 결과가 이미 있다. 이를 놓치고 fast/history 대비와 예산 연장을 중심으로 설명했다. 기존 비교를 다시 공개한 [전체 표](tcn_merit_existing_20261124.md)는 원본 점추정·구간을 옮긴 것이며 새 채점이 아니다.

또한 두 종류의 2단계를 구분한다.

| 이름 | 실제 구성 | 현재 확인 가능한 것 |
|---|---|---|
| 현행 원고 estimator | 인과 GP + history/fast/anchor 요약의 부스팅 잔차 회귀 | B.94에 동일 채점 행의 TCN 대비가 있음 |
| 과거 순환 모델의 2단계 | LSTM + 후단 보정 | D1 재채점 파일은 있음. 새 TCN과 분할·행·시나리오 재생 정합은 미확인 |

뒤의 모델을 앞의 모델 결과로 대신하지 않는다. 과거 정리 이전의 줄기나 숫자는 복원하지 않는다.

## 이미 확인한 근거와 남은 질문

네 검증 설계와 두 기존 scope를 분리한 전체 결과는 연결 표에 있다. 현행 진단 포함 GP+부스팅을 대체할 TCN의 정확도 근거는 현재 약하다. 이력이 오래된 시나리오의 fast/history 양수 skill은 현행 estimator 대비 merit와 다른 질문이다. B.104에서 진단 포함 체크포인트는 예산 연장으로 바뀌지 않았다.

B.84에는 이미 시나리오 혼합으로 한 번 학습한 `TXall/T0all`이 있다. 따라서 “여러 조건에 모델 하나”만으로 TCN의 운용 장점을 주장하지 않는다. B.84는 **L5만 있고 V2가 없다**. 다른 설계/표적으로 확장된 결과처럼 쓰지 않는다. D10에서 학습해 그대로 적용한 `TXa`만 약한 대조로 골라 개선을 주장하지 않는다.

메타데이터 점검에서 저장된 혼합 회귀기·조건별 회귀기의 비교 가능한 row-index 지원이 확인됐다. 이는 목표값·manifest·입력 정보의 일치 검증까지 끝났다는 뜻은 아니다. 값 배열을 읽지 않은 점검이며 신규 skill/구간은 계산하지 않았다.

TCN의 정보 차이는 구체적이다. 현 구현은 입력을 앞 22채널로 잘라, 데이터 준비에 이미 있는 source-time fast 13채널을 버린다. GP+부스팅에는 anchor 요약이 있다. 단, 이 TCN도 시간 문맥을 가지므로 “anchor 정보를 전혀 모른다”거나 이것이 성능 차이의 원인이라고 단정하지 않는다. 신경망은 외부 fit 파일의 일부를 내부 VAL로 남기고 기존 회귀기는 그 파일까지 적합에 썼다는 차이도 있다.

## 실행 순서와 중단 기준

### 1. GPU 전: 비교 계약과 재사용 검사

새 배치 등록·커밋 전에 다음을 새 파일로 구현하고 별도 검증한다. 기존 동결 코드와 결과는 수정하지 않는다.

- 기존 B.94의 paired TCN/현행 회귀기 결과를 판정표의 첫 줄에 놓는다. 이미 있는 수치를 GPU로 다시 만들지 않는다.
- TCN 대 혼합 회귀기와 D10 고정 적용 회귀기는 기존 저장 예측으로 비교한다. 새 비교/재표집은 별도 실행 사전등록 커밋 **후**에만 한다. 모든 지원 행, 제외 수, fit/test manifest, F/L5 정의, CES 처리, source 가용 규칙을 대조한다. 누락 모델은 누락으로 남긴다.
- 과거 LSTM+후단 보정은 원래 가용 범위의 분할·행 대응부터 조사한다. 정합되지 않으면 수치 비교를 만들지 않고 비교 불가로 기록한다. D10 모델을 임의로 지연 시나리오 모델로 바꾸지 않는다.
- 기존 회귀기는 신경망 내부 VAL을 적합에 썼으므로, 그 저장 예측으로 신경망 VAL 선택을 하면 안 된다. VAL 비교용 회귀기는 **신경망의 동일 내부 TRAIN 파일만** 써 CPU에서 새로 적합하고 GP 설정도 그 TRAIN에만 묶는다. 이 적합도 사전등록 대상이다. VAL에서 CES의 과거 관측을 인과 입력으로 쓰는 것과 그 라벨로 학습하는 것을 구분한다.

이 과정만으로 실용 merit가 지지되지 않고 아래 정보 차이 질문을 남길 이유도 없으면 **GPU 0회로 종료**한다. “CPU만 했다”는 실패가 아니라 불필요한 재학습을 줄인 결과다.

### 2. 조건부 GPU 선별: 후보는 anchor 입력을 명시한 TCN 하나

새 TCN 탐색을 계속한다면 다음 **단일 변경만** 허용한다. 잔차화·NBI·새 loss·새 backbone을 동시에 넣지 않는다.

| 항목 | 고정 방향 |
|---|---|
| 질문 | 현재 TCN이 버린 source-time fast 채널을 제공하면 현행 estimator에 접근하는가? |
| 후보 | 같은 causal TCN에 기존 13 anchor-fast 채널을 더한 35채널 입력. source가 없으면 0과 기존 has-visible flag 사용 |
| 단위 | 이전에 고정한 `V1_r2_k0`, `V2_s1_k0`, `V3_q3`, `V4a` 전부 |
| 초기화/총량 | 기존 첫 seed 1701, 단위당 하나, **새 production fit 최대 4개** |
| 대조 | 같은 내부 TRAIN의 GP+부스팅, 기존 22채널 TCN. TEST에서는 원래 현행 estimator도 별도로 유지 |
| 표적/입력 | F와 L5 유지. 가용 규칙 혼합과 K10 학습/VAL 제외 유지. 현재/미래 CES는 입력 금지 |
| 학습 | 원래 AdamW, LR, batch16, dropout, 표준화, 정규화, scheduler, patience6, 40epoch 유지 |
| 예산 | 경로당 soft cap 3600초. 기존 체크포인트의 연속 학습이 아닌 새 적합. 이전 TCN의 예산과 다름을 공개 |
| 선택 | seven-rule × two-head에 동일 가중치를 둔 기존 VAL loss로 best checkpoint 선택 |
| 실행 | 기존 qualified CUDA 경로 사용. 새 35채널 모델의 실자료 smoke·메모리·정상 종료 확인 후 최대 4동시, 불충분하면 줄임 |

최소 source-time 검사: anchor index가 현재보다 앞이며 동일 segment/file에 속함; 보이지 않는 CES/미래 fast/TEST label 변조가 입력 prefix를 바꾸지 않음; TRAIN-only 통계; batch와 step 예측 일치; segment reset; 결측 source 처리; best 체크포인트 재로드. 실패 시 배정을 중단하고 관련 없는 GPU 프로세스는 건드리지 않는다.

이 후보는 같은 정보 접근을 설명하기 위한 탐색이다. 전체 fast 시계열과 요약 피처가 동일 표현은 아니고 학습 예산도 다르므로 순수한 아키텍처 우열이라고 부르지 않는다. 기존 learned-anchor LSTM 후보의 결과가 이 TCN 변경을 검증한 것으로 취급하지도 않는다.

### 3. VAL에서 전체 확장 여부를 먼저 결정

운용상 비열등 margin은 앞선 프로토콜의 **MSE 증가 5%**를 그대로 제안한다. 이는 물리적으로 검증된 허용 오차가 아니며 등록할 운용 기준이다. 네 설계 중 어느 것도 primary로 지정하지 않는다.

선별 판단은 새 TEST를 보기 전에 한다. 같은 내부 TRAIN으로 적합한 GP+부스팅 대비, 각 고정 unit에서 기존 동일 가중 VAL 평균 MSE 비율이 모두 1.05 이하일 때만 후속 검토 자격을 준다. F와 L5별 VAL 요약도 분리해 공개한다. 이는 구간 없는 **계산 자원 배정 기준**이며 비열등성의 통계적 증거가 아니다. 그 외에는 해당 후보를 종료하고 내일 추가 fit은 하지 않는다. 경계가 애매하다는 이유로 seed나 하이퍼파라미터를 추가하지 않는다.

선별 통과 후에도 같은 날 자동으로 15단위/다중 초기화로 확장하지 않는다. TEST 판정 기준과 전체 범위/초기화 수를 별도 등록해 소스·숫자 검증을 마친 뒤 진행한다. 한 unit당 한 초기화로 “네 설계에 강건하다”는 결론을 내리지 않는다.

최종 merit의 세 경로는 다음과 같다.

1. **정확도:** 현행 estimator 대비 paired MSE skill의 95% 구간 하한이 0보다 큰지, 사전 지정 셀과 네 설계 모두에서 보고한다.
2. **운용:** 정확도 비열등은 skill 구간 하한 > −0.05로 판정한다. 이와 별도로 동일 CPU 환경의 전처리·모델·상태 메모리와 지연을 실제 측정해야 한다. 현재 TCN 순전파 시간만으로 더 빠르다고 주장하지 않는다.
3. **시나리오:** 고정 적용과 혼합 학습, 조건별 재적합 대조를 구분하고 비교한다. 약한 고정 적용 대조 하나에 대한 차이만으로 채택하지 않는다.

여러 셀의 유리한 결과를 하나 고르는 판정은 하지 않는다. 전체 셀을 제시하고 범위 전체 주장은 사전 지정 셀/설계가 전부 충족하는 conjunction으로 제한한다. 특정 조건의 개별 양수 발견을 주장하려면 등록한 비교군에 Holm 보정을 별도로 적용한다. 기존 원본 구간을 동시구간으로 바꾸어 부르지 않는다.

## 시간과 실제 준비 상태

GPU 선별을 하게 되면 학습 자체는 4동시가 확인됐을 때 최대 약 1시간의 soft budget이다. 준비·smoke·VAL 비교·검증을 포함해 **2시간 30분의 전체 작업 예산**을 제안하며, 이는 측정된 완료 예상시간이 아니다. 4동시가 불가능하면 같은 총량 안에서 완료 가능한 것만 보고하고 자동 연장하지 않는다. CPU 비교가 먼저 중단 판정을 내리면 GPU 시간은 쓰지 않는다.

현재 완료된 것은 기존 paired 결과 공개, index/mask 재사용 목록, Fable 검토와 이 방향 문서다. **35채널 학습 runner, 새 비교 scorer, 내부 TRAIN 회귀기 재적합, 실행 등록은 아직 준비 완료가 아니다.** 따라서 지금 복사해 실행할 GPU 명령이 있다고 말하지 않는다. 다음 세션은 이 문서를 기준으로 새 배치의 구현·독립 검증·등록 커밋부터 시작하며, 원래 B.94/B.104 큐는 재실행하지 않는다.

## Fable 의견에서 작업자가 수정한 부분

[Fable 원문과 사용량](tcn_merit_fable_20261124.md)은 조언이며 검증 결과가 아니다.

- 두 번째 요청은 핵심 overview만 다시 보냈다. 따라서 Fable이 첫 요청의 전체 셀 언급을 “제공되지 않은 수치”라고 한 부분은 잘못이다. 첫 요청에는 전체 136셀을 제공했다. 전체 표는 API 서술이 아니라 원본 JSON으로 생성했다.
- “주 설계”를 고르라는 제안은 채택하지 않는다. 원래 네 설계를 동등하게 보고한다.
- 한 시간분할의 세 초기화만 선별하자는 제안은 네 고정 unit의 첫 초기화로 바꿨다. 이는 선별이며 초기화 강건성 검증은 아니다.
- “정보 일치 질문에는 저자의 별도 명시가 필수”라는 조언은 승인 요구로 해석하지 않는다. 현재 지시에 따라 준비할 수 있다. 다만 동결 실행과 신규 적합의 사전등록은 지킨다.
- “영구 중단” 대신 현재 후보의 종료로 한정한다. 새로운 독립 근거가 생기는 것까지 금지하지 않는다.
- B.84의 L5/V2 범위 제한, 내부 VAL에 이미 적합한 기존 회귀기를 VAL 선별에 쓰면 안 된다는 제약을 추가했다.
