## 2. 데이터

- 형식: shot 하나당 CSV 1개, 파일명 `s<shot번호>.csv`. **총 641개**.
- 위치: 저장소 `data/` (gitignore 대상, 커밋되지 않음). 다른 위치를 쓰려면
  `CES_DATA_DIR`을 그 폴더로 지정.
- 필수 컬럼: `time`, `CES_TI`, `CES_VT`, 그리고 접두사로 인식되는
  `BES_*`(9채널), `ECEI_*`(4채널), `MC*`(2채널). 피처 컬럼은 CSV 헤더에서 접두사로 **추론**된다.
- 시간 격자: 10 ms. 결측률(641 shot / 247,207행 전수 집계): NaN 결측은 `CES_TI` 8.2%,
  `CES_VT` 23.9%. `CES_VT`는 held(직전 관측값과 bit-identical) 41.1%가 추가되어 **실질 무정보
  65.0%** (관측값 중 54.0%가 held, 499/641 파일, 최대 연속 1,214행). `CES_TI`의 held는 1행뿐.
  두 타겟은 독립적으로 결측.
- 연속 블록 판정: `time` 차분 `< 0.5 s`이면 같은 연속 블록.
- 디스크 캐시: `data/.ces_cache/*.npz`. 키 = window 크기 + 증강 플래그 + 컬럼 + 파일 크기/mtime 해시.
  해당 값이 바뀌면 자동 무효화.

### 2.1 CES_VT held(forward-fill) 값 감사 결과 (기록치)

- 관측된 `CES_VT` 값 중 **약 54%**가 같은 연속 블록 안에서 직전 관측값과 **bit 단위로 동일**한
  반복값(최대 1214행 연속, 641개 파일 중 499개 영향). `CES_TI`는 **0.0%**.
- 코드상 처리: `dataset.py`의 `drop_stuck_targets` 플래그(`_nan_out_stuck_targets`,
  `_stuck_repeat_mask`)로 해당 값을 NaN 처리 가능.
- 기본값이 스크립트마다 다르다: `train.py`는 `CES_DROP_STUCK_TARGETS` 기본 **0**(유지),
  `evaluate.py`는 기본 **1**(제거).

## 4. 데이터/모델 계약 (모든 실험에서 불변)

이 계약은 `model.py`, `train.py`, `dataset.py`가 공통으로 의존하고
`tests/test_architecture.py`가 일부를 assert한다.

- `model.forward(self, bes, ecei, mc, time_features=None, ces_history=None)` — 시그니처 고정.
- 출력은 정규화된 `[CES_TI, CES_VT]`, shape `(batch, 2)`. **`model.py` 내부에서 역정규화 금지.**
- BES/ECEI/MC/타겟은 채널별 z-score, 통계는 **학습 파일에서만** 추정
  (`fit_normalization_stats(train_files)` → `set_normalization_stats`). 타겟 통계는 NaN-aware.
- `ces_history`는 `(batch, window, 4)`: 이전 정규화 `CES_TI`, 이전 정규화 `CES_VT`,
  `CES_TI` 관측 flag, `CES_VT` 관측 flag. **타겟 시점은 값·flag 모두 0으로 완전 마스킹.**
- 각 샘플에 `target_mask` `(batch, 2)`. 학습/검증 손실은 **per-target masked MSE**.
  행 유지 조건 = 입력이 온전하고 `CES_TI`/`CES_VT` 중 **최소 하나** 관측.
- `time_features`는 4채널: lookback 초, delta 초, `log1p(lookback)`, `log1p(delta)`.
- 학습 손실 = masked MSE + `0.1 * relu(zero_ti_normalized - pred_TI).mean()`,
  grad clip `max_norm=5.0`, `AdamW(weight_decay=1e-4)`, `ReduceLROnPlateau(patience=2, factor=0.5)`.

### 5.3 split 생성 규칙

- 분할은 **행 단위가 아니라 CSV(shot) 파일 단위**, seed 고정.
- 각 쪽은 seed 고정 랜덤 서브셋으로 샘플 수 상한(cap)까지 잘라낸다.
- 결과는 `CES_SPLIT_DIR/fixed_{train,val}_split.csv`로 디스크에 고정. 재로드 시
  `load_fixed_split_csv`가 각 샘플의 파일/행을 다시 계산하고 **데이터셋과 불일치하면 예외를 던진다**.
  재생성하려면 split CSV를 삭제한다. 샘플 cap을 바꿔도 재생성된다.
- `CES_TEST_FRACTION > 0`이면 `load_or_create_3way_splits`가 train/val/test 3분할을 만들고
  manifest에 `test_files`를 기록한다.

### 6.3 보간 baseline · 3-way split · 사전등록 (2026-06-22 ~ 06-23)

새로 만든 코드와 검증 방식:

1. `baselines_interpolation.py` — 블록 이웃에 대한 linear / PCHIP / local AR / (GP).
   - 타겟 자기 행 제외(누수 없음), **≥0.5 s gap에서는 보간 거부 → persistence로 fallback**.
   - 단위 테스트 7개 통과.
2. `evaluate.py` — 공통 `build_clean_val_subset()` 추출. 삭제 후 재생성으로
   **byte-identical 회귀 가드** 확인.
3. `compare_baselines.py` — 모델 vs 보간, 물리단위, PCHIP를 headline으로,
   **모든 arm을 동일한 `(file, row_index)` 샘플 집합과 동일한 per-target mask**로 채점,
   Δt bin별 계층화, per-shot 제곱오차를 npz로 저장.
4. `bootstrap_compare.py` — shot을 재표본 단위로 하는 paired bootstrap
   (`B=10000`, seed `12345`), 집계 + small-gap.
   - `tests/test_bootstrap_compare.py` 9개 통과. 리뷰에서 MED-1(0-division) 수정.
5. `train.py` — 3-way train/val/test split + `CES_INIT_SEED` 추가.
   `CES_TEST_FRACTION=0`이면 기존 2-way와 동일(하위 호환). pytest 10/10 통과.
6. 사전등록 규칙 PR1–PR4는 TEST 수치를 보기 **전에** 고정했다(당시 사전등록 문서는
   `.omc/` 에이전트 스크래치에 있었고 2026-08-09에 제거 — git 이력에 남아 있다):
   - PR1 headline baseline = PCHIP.
   - PR2 보간은 모델이 채점되는 모든 관측 타겟에서 예측(미래 이웃 없으면 persistence fallback).
   - PR3 TEST 최소 규모 ≥15 shot & ≥3,000 관측 `CES_TI`.
   - PR4 shot-clustered bootstrap 95% CI가 0을 제외하면 PASS.
7. 참고문헌 정리: `docs/interpolation_baselines_references.md`.
8. 분석 모듈 정합성 리뷰 수행(누수 없음, 동일 샘플, persistence 교차검증,
   bootstrap 구현 검증). 리뷰 노트는 `.omc/`와 함께 제거 — git 이력 참조.

### 6.4 개선 루프 — 선택 기준을 val loss → clean `skill_vs_pchip`으로 교체

`program.md`의 목적함수를 "val split에서 `compare_baselines.py`가 보고하는
`CES_TI`/`CES_VT` `skill_vs_pchip`의 평균"으로 바꾸고 10 iteration 실행.
test split은 선택에 사용하지 않음.

- 루프 1 iteration의 단계: **param 수 카운트(예산 초과 시 학습 없이 폐기) → 스모크 검증 →
  전체 `train.py` → clean `evaluate.py` / `compare_baselines.py` → 점수 비교 →
  KEEP(신기록) 또는 DISCARD(+`model.py`를 최고 스냅숏으로 롤백)**.
- 상태: `<output_dir>/.automl_state/best_model.py` + iteration별 아카이브
  `<output_dir>/.automl_state/history/model_iterNNN.py`.
- 연구자 역할: 로그인된 `claude` CLI(구독 과금) 기본, `ANTHROPIC_API_KEY`가 있으면 SDK 경로.
  모델 기본값 `claude-opus-4-8`, `AUTOML_RESEARCH_MODEL`로 변경 가능.
  출력은 raw `model.py` 한 덩어리여야 하고 `class MultimodalCESPredictor`와 `def forward` 포함 여부를 검사.

### 6.6 peak(고변동 구간) 분석 (2026-06-23)

재학습·계약 변경 없이, 이미 저장된 val split 오차 npz만 다시 자르는 방식.

- 절차: `compare_baselines.py`를 `CES_SPLIT_TAG=val`로 실행 → `comparison_errors_val.npz` 생성
  → `peak_analysis.py` 실행.
- peak 정의(Family i-a `ces_activity`): **타겟 행을 제외한** 이웃 집합(`build_neighbor_set`)에서
  계산한 큰 이웃-bracket 기울기 및/또는 높은 국소 CES-이웃 분산. 즉 `CES[idx]`를 읽지 않는
  입력 기반 proxy이며 pointwise 극값이 아니다.
- npz에는 additive key `{name}_is_peak` 하나만 추가되고, headline peak SE는 전역
  `compare_baselines.py` SE와 byte-identical.
- 통계: shot-clustered paired bootstrap (B=10000, seed 12345),
  충분성 가드 `N_MIN_PEAK_SHOTS=15`(구속) / `N_MIN_PEAK_ROWS=200`.
- AC7 ablation: `CES_PEAK_ABLATION=1`로 게이트. `no_fast` arm은 BES/ECEI/MC를 0으로.
  부호 규약 고정 `paired_diff = SE_no_fast − SE_full`, 유의 판정은 `paired_diff_ci95[0] > 0`.
- 민감도 sweep 3설정: `(slope_z, neigh_var_pct)` = (2.5, 0.10) 기본 / (3.0, 0.05) / (2.0, 0.20).

기록치 (기본 파라미터, val, 8000-sample eval, `data/.improve_final_out`):

| target | 전역 skill_vs_pchip | peak skill | peak 95% CI | rows / shots |
|---|---:|---:|---|---:|
| CES_TI | +0.515 | +0.855 | [+0.658, +0.933] | 965 / 119 |
| CES_VT | +0.241 | +0.691 | [+0.107, +0.871] | 1760 / 82 |

AC7 기록치: `CES_TI` diff CI ≈ [+2066, +36997], `CES_VT` diff CI = [0, 0].
(`THESIS_RESULTS.md` §5.1에는 최종 체크포인트 기준 재산출값 CES_TI +0.702 / CES_VT +0.438이 기록되어 있다.)

### 6.7 파라미터 예산 sweep (2026-06-24)과 <1M 예산 루프

- 통제 sweep: 동일 regime, 단일 seed, val split. GRU 계열(`data/.sweep_g_*`, `data/.sw2_g_*`)과

  (d_model≈192, nhead 4, ff≈2×, ≈0.79M params). 1M 초과 설정은 모두 낮은 점수.

  iter5–19 전부 롤백, iter20은 학습 단계 실패(FAILED). stale rounds 16.

## 8. 재현 시 반드시 지켜야 하는 절차적 함정

1. **아키텍처 선택은 `CES_MODEL_FILE`로 한다 (2026-08-09~).**
   `ces_prediction/model.py`는 논문 아키텍처 `model_iter009.py`를 재수출하므로 기본값이
   이미 옳고, 저장 체크포인트가 그대로 로드된다. 변형 아키텍처를 쓰는 실험은 하위
   프로세스 env에 `CES_MODEL_FILE=<변형 .py 경로>`를 넣는다
   (참조 구현: `ces_prediction/experiments/anchor/run_anchor_experiments.py`).
   **`model.py`를 덮어쓰는 예전 방식(`swap_in_iter009`/`.wsweep_backup`)은 제거됐다** —
   되살리지 말 것. 배치가 중간에 죽으면 추적 중인 소스가 깨지던 방식이다.
2. **`data/.improve_final_out/weights/`와 `data/.ms_out_*/weights/`는 기록 수치를 만든
   체크포인트가 아니다.** 현재 신뢰 계열은 `data/.vt_repro_*`.
   어떤 체크포인트든 쓰기 전에 그 디렉터리의 기록 metric과 대조할 것.
3. **`train.py`는 `CES_SPLIT_DIR/split_manifest.json`을 덮어쓴다.**
   `CES_TEST_FRACTION=0`(기본)이면 2-way manifest를 써서 3-way split 디렉터리의
   `test_files`를 **파괴**한다. manifest를 백업하거나 split 디렉터리 복사본을 가리킬 것.
4. **평가 루프를 직접 구현하지 말 것.** `compare_baselines`는 baseline이 정의되지 않는
   `CES_TI` 샘플 약 160개를 제외한다. 이 소수 행(최대 15 keV의 CES fit 실패값)이
   RMSE를 13% 흔든다.
5. **split CSV 재생성**: 데이터셋이 바뀌면 `load_fixed_split_csv`가 예외를 던진다.
   재생성하려면 split CSV를 지운다.
6. **AutoML 루프는 Slack이 없으면 학습 전에 실패한다** (`validate_slack_config`).
   `slack_sdk`, `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID` 모두 필요.
7. **일회성 실험은 반드시 별도 `CES_SPLIT_DIR` / `CES_OUTPUT_DIR`** 로 격리한다
   (정식 split/metrics/weights 덮어쓰기 방지).
8. **데이터가 없으면 대부분이 돌지 않는다.** `tests/` 3개 중 `test_dry_run`만 데이터 없이 동작.
9. `CES_TI` > 약 3 keV 값은 스펙트럼 fit 실패 산물이며(전역 p99 = 2,089 eV, 최대 14,984 eV)
   평가 모집단에 남아 있다. 그림 스크립트는 `TI_BAND=(20, 3000)`, `VT_BAND=(−60, 300)`로 밴딩한다.

  `refs_litreview.bib`)은 판정이 끝난 뒤 제거됐다 — git 이력 참조. **살아있는 산출물은
  판정 문서 `docs/paper/NOVELTY.md`와 최종 참고문헌 `docs/paper/refs.bib` 둘뿐이다.**
- `NOVELTY.md` 생성 방식(기록): 4개 병렬 탐색 에이전트(targeted / fusion-ML / adversarial novelty /
  ML methods), 25개 이상 쿼리 변형, 후보는 OpenAlex로 검증(S2 keyless 풀 포화로 fallback).

### 9.4 문서 갱신 규칙 (AGENTS.md / CLAUDE.md에 명시된 운영 규약)

- `THESIS_RESULTS.md` §8 — 의미 있는 run마다 설계·결과·판정을 기록 (per-run 로그).
- `PROJECT_KNOWLEDGE.md` — 지속되는 교훈만 승격 (장기 기억, per-run 로그가 아님).
- (`HANDOFF.md` / `PROGRESS.md`는 AutoML 루프와 함께 2026-08-05에 제거됐다.)
- 통제 변수는 한 번에 하나만 변경.
- 코드 변경 후 `python -m pytest -q`, 학습/데이터/모델 동작이 바뀌면 스모크 학습도 실행하고 결과 기록.
- git commit/push는 사용자가 그 메시지에서 명시적으로 요청할 때만 수행.
